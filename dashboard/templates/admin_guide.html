Super User Guide
Full reference for managing the BootHop Pipeline system — logins, server, schedules, API credentials, and troubleshooting. This page is protected and only visible when logged in as admin.

System Overview

BootHop Pipeline is a Python-based FastAPI application running on Oracle Cloud. It finds trending topics, writes scripts using GPT/Perplexity, renders short-form videos, and posts them to social platforms on each client's agreed schedule. The admin portal manages all client accounts from one place.

ServerOracle Cloud Free Tier — Ubuntu 22.04 — 140.238.73.32
App path/opt/otb_pipeline
Auto-deployCron pulls from GitHub every 5 minutes — push to main branch to deploy
DatabaseSQLite at dashboard/otb.db — not committed to git (server-only file)
Process managersystemd service otb-pipeline — restart with sudo systemctl restart otb-pipeline
Environment vars/opt/otb_pipeline/keys.env — sourced by systemd service unit

Pipeline stages
1. Query Bank refresh → 2. Trending hook selection → 3. Script generation (GPT/Perplexity) → 4. Video render (Kling AI or Pexels fallback) → 5. Post to platforms → 6. Telegram notification to client

Oracle Server — SSH Access

ssh -i ~/.ssh/oracle_boothop.pem ubuntu@140.238.73.32

The SSH key file is oracle_boothop.pem. Keep this safe — it is the only way to access the server directly. If you are on a new machine, copy the key over and chmod 400 oracle_boothop.pem first.

Useful server commands

cd /opt/otb_pipeline          # go to app directory
sudo systemctl status otb-pipeline   # check if app is running
sudo systemctl restart otb-pipeline  # restart after config changes
journalctl -u otb-pipeline -f        # live log stream
cat keys.env                         # view environment variables
git pull                             # manual pull (auto-pull runs every 5 min)

keys.env — environment variables

Located at /opt/otb_pipeline/keys.env. Add or edit API keys here. After editing, restart the service:

sudo nano /opt/otb_pipeline/keys.env
sudo systemctl restart otb-pipeline

Deployments

The server pulls from GitHub's main branch every 5 minutes via a cron job. Normal workflow:

  1. Make changes locally and commit to main branch
  2. Push to GitHub: git push origin main
  3. Within 5 minutes the server auto-pulls and the app restarts
  4. To deploy immediately: SSH in and run cd /opt/otb_pipeline && git pull && sudo systemctl restart otb-pipeline
Database file
dashboard/otb.db is in .gitignore — it never gets overwritten by git pull. Client data is safe. If git pull says the DB is blocking the merge, run git checkout dashboard/otb.db first, then pull.

cron.org — Schedule Management

Each client's pipeline runs are triggered by cron.org firing HTTP GET requests to the Oracle server. cron.org runs in UTC — the admin company page automatically converts each client's local time slots to UTC when you save a schedule.

Login: cron.org — use the BootHop account credentials stored in your password manager.

Adding a cron job for a new client

1

Open the admin company page

Go to /admin/company/{id} → Schedule tab. Set the timezone and time slots, then click Save. The UTC cron expression is shown automatically — copy it.

2

Create job on cron.org

Log in to cron.org → New Job. Paste the cron expression. URL format: http://140.238.73.32:8000/run-pipeline/{slug} — replace {slug} with the client's Company ID.

3

Test it

Use cron.org's "Test Job" button to fire the job manually and verify the pipeline runs. Check the Telegram notification arrives.

DST handling
The schedule page shows a DST warning for UK and US timezones. When clocks change (UK: last Sunday in March/October; US: first Sunday in November), cron.org UTC times must be updated manually. The admin page recalculates the correct UTC times if you re-save during those weeks.

Client Onboarding Workflow

  1. Client fills in intake form at boothop.com/get-started. This creates a DB record with intake_status=submitted.
  2. You see it in admin portal under Intake Queue (amber highlight). Review their answers.
  3. Onboarding call — agree on platforms, posting times, content style, and tone.
  4. Set up credentials — go to /admin/company/{id} → Credentials tab. Enter all API tokens for the platforms they want to use.
  5. Set the schedule — Schedule tab. Choose timezone, pick time slots, copy UTC cron expression to cron.org.
  6. Set status to Active — Profile tab → Status → Active. This allows the pipeline to run.
  7. Set their password — Profile tab or send a password reset link from /forgot-password.
  8. Share their login details — Company ID, password, and link to boothop.com/pipeline-login.
  9. Get their Telegram Chat ID (see below) and add it to their profile.
  10. Run first pipeline manually — trigger via cron.org Test Job or the admin Run button.

Getting a Client's Telegram Chat ID

Every client needs a Telegram Chat ID so the pipeline can send them notifications. Two ways to get it:

Method A — Client does it themselves (preferred)

Direct the client to the /manual page → "Setting up Telegram" section. They open Telegram, find @userinfobot, send any message, and copy their ID from the reply. They send you the number.

Method B — They forward from your bot

Ask the client to start a chat with your pipeline bot (find it in Telegram by the bot username). When they start the bot, your bot logs the chat ID in the Telegram commander — check the commander or live logs for "New user started bot" messages.

Method C — They are already messaging you

If the client has already sent you a WhatsApp or Telegram message, get their number and use the Telegram admin forward — forward a message from their chat to @userinfobot to get their ID. (Only works if they are on Telegram.)

TikTok API Credentials

TikTok uses OAuth 2.0. You need a TikTok developer account and a registered app for each client (or one app with multiple user tokens).

Step-by-step: get a TikTok access token

1

Create a developer account

Go to developers.tiktok.com. Sign in with a TikTok account (create a business account if needed). Click "Manage Apps" → "Create App".

2

Set up the app

App name: "BootHop Pipeline". Category: Social Media Tools. Platform: Web. Redirect URI: https://boothop.com/oauth/tiktok/callback (or any URL you control — you just need to capture the code). Request scopes: user.info.basic and video.upload.

3

Have the client authorise

Construct the OAuth URL using your client_key and send it to the client. They click it, log in to their TikTok, and approve. TikTok redirects back with a code parameter in the URL.

4

Exchange code for token

POST the code to TikTok's token endpoint with your client_key and client_secret. You get back an access_token (valid 24h) and a refresh_token (valid 365 days). Store the refresh token — it is used to silently get new access tokens.

5

Add to client credentials in admin portal

Go to /admin/company/{id} → Credentials tab. Paste the access token and refresh token. The pipeline refreshes automatically before each post.

TikTok token expiry
Access tokens expire after 24 hours. Refresh tokens expire after 365 days. The pipeline auto-refreshes access tokens but if the refresh token expires (or the client revokes access), posting will fail and you will get a Telegram alert. Re-run the OAuth flow to get a new refresh token.

Instagram & Facebook API Credentials

Instagram and Facebook both use the Meta Graph API. You need a Facebook Page linked to an Instagram Business account, and a Meta developer app.

Pre-requisites (client must do this first)

  • The client's Instagram account must be an Instagram Business or Creator account (not a personal account). Change this in Instagram Settings → Account → Switch to Professional Account.
  • The Instagram account must be linked to a Facebook Page. Go to Instagram Settings → Account → Linked Accounts → Facebook.
  • The client must be an admin of that Facebook Page.

Step-by-step: get an access token

1

Create a Meta developer app

Go to developers.facebook.com. Log in as BootHop (or an admin account). Click "Create App" → choose "Business" type → fill in app name "BootHop Pipeline".

2

Add the Instagram Graph API product

In the app dashboard, click "Add Product" → "Instagram Graph API". Also add "Facebook Login" if you need Page posting.

3

Get a short-lived User Token

Use the Graph API Explorer at developers.facebook.com/tools/explorer. Select your app. Click "Generate Access Token". Approve all the permissions needed: pages_show_list, pages_read_engagement, pages_manage_posts, instagram_basic, instagram_content_publish. Copy the short-lived token.

4

Exchange for a long-lived token

Call the Graph API: GET /oauth/access_token?grant_type=fb_exchange_token&client_id={app_id}&client_secret={app_secret}&fb_exchange_token={short_lived_token}. This gives you a 60-day User Access Token.

5

Get the Page Access Token

Call: GET /me/accounts?access_token={long_lived_user_token}. The response lists all pages the user manages, each with its own access_token. Page access tokens do not expire — use these for posting.

6

Get the Instagram Account ID

Call: GET /{page_id}?fields=instagram_business_account&access_token={page_token}. Copy the id from instagram_business_account. This is your Instagram Account ID — needed to post Reels.

7

Add to admin portal

Save the Page Token, Instagram Account ID, and App ID + Secret to the client's Credentials tab.

Page tokens don't expire
Unlike User tokens, Page Access Tokens generated from a long-lived User token are permanent (until the user revokes access). These are what the pipeline uses for all Facebook and Instagram posts.

YouTube API Credentials

1

Google Cloud Console

Go to console.cloud.google.com. Create a new project "BootHop Pipeline". Enable the YouTube Data API v3 (search in API Library).

2

Create OAuth 2.0 credentials

APIs & Services → Credentials → Create Credentials → OAuth 2.0 Client ID. Type: Web Application. Add redirect URI: https://boothop.com/oauth/youtube/callback.

3

OAuth consent screen

Set up the consent screen. Add scopes: https://www.googleapis.com/auth/youtube.upload. Add the client's Google account as a test user (until the app is verified).

4

Authorise the client's channel

Send the OAuth URL to the client. They log in to their Google account and approve access. Capture the authorisation code and exchange it for tokens (access_token + refresh_token). Store the refresh token — access tokens expire after 1 hour but the refresh token lets you get new ones silently.

LinkedIn API Credentials

1

LinkedIn Developer App

Go to linkedin.com/developers. Create an app — use the BootHop company page as the associated company. Select products: Share on LinkedIn and Sign In with LinkedIn using OpenID Connect.

2

OAuth flow

Request scopes: w_member_social (post on behalf of member) or w_organization_social (post on behalf of company page). Send client the OAuth URL. Capture the code and exchange for an access token.

3

Token expiry

LinkedIn access tokens expire after 60 days. There is no refresh token — you must re-run the OAuth flow every 60 days. The pipeline will alert you via Telegram when a token is about to expire or fails.

LinkedIn caveat
LinkedIn's API has strict rate limits and video upload is via a multi-step media upload API. Confirm video specs before enabling this for a client: MP4, under 5GB, 3s–10min, 256×144 to 4096×2304.

Pexels & Pixabay Stock Footage

These are used as fallback footage when the client has no personal clips and Kling AI is unavailable or has no credits.

PexelsCreate account at pexels.com → Your Profile → API tab → "New API Key". Free for non-commercial; check licence for commercial use. Rate limit: 200 requests/hour.
PixabayCreate account at pixabay.com → Explore → API → "Get API Key". Free with attribution. Rate limit: 100 requests/minute.

Both keys are global pipeline keys (not per-client) — they go in keys.env as PEXELS_API_KEY and PIXABAY_API_KEY.

Asset cooldown
All stock footage (Pexels, Pixabay) and all client-uploaded clips have a 14-day cooldown — the same clip is never used within 14 days of its last appearance. This is enforced in the render script.

WhatsApp Business API

WhatsApp Business API is used if a client wants to receive pipeline notifications via WhatsApp instead of (or as well as) Telegram. This is more complex to set up than Telegram and has a monthly cost.

Requirements

  • Meta Business Account (same as Facebook)
  • A dedicated phone number that is not already on WhatsApp (can be a virtual SIM)
  • Business verification on Meta — takes 1–5 days

Step-by-step

1

Set up Meta Business account

Go to business.facebook.com. Create or log into your Meta Business account. Complete business verification (requires business name, address, and verification document).

2

Add WhatsApp to your Meta app

In your existing Meta developer app (the same one used for Instagram), click "Add Product" → "WhatsApp". Follow the setup wizard. Add a phone number.

3

Get a permanent system token

In Meta Business Manager → System Users → Create a system user. Assign the WhatsApp app permissions. Generate an access token — this does not expire unless manually revoked.

4

Get the Phone Number ID

In the WhatsApp section of your app dashboard, you will see the Phone Number ID next to your registered number. This is needed in every API call.

5

Send test message

Use the "Send and receive messages" panel in Meta developer app to send yourself a test message. Verify delivery before going live.

Cost & complexity
WhatsApp Business API charges per conversation (around $0.03–$0.10 per 24-hour conversation window depending on country). For simple pipeline notifications, Telegram is free and simpler — only offer WhatsApp notifications as a premium add-on.

Troubleshooting

Pipeline not posting — no Telegram notification

  1. SSH into Oracle: journalctl -u otb-pipeline -f — look for errors in the last run
  2. Check intake_status is active for that client (admin portal → company page)
  3. Verify cron.org job is enabled and the URL is correct — fire a Test Job manually
  4. Check the TELEGRAM_TOKEN is valid — try sending a test message manually with curl

Pipeline runs but posts fail on a specific platform

  1. Check the platform token in Credentials tab — it may have expired
  2. TikTok: refresh token may need renewal (annual OAuth re-flow)
  3. Instagram: check the Facebook Page is still linked to the Instagram Business account
  4. LinkedIn: token expires every 60 days — re-run OAuth flow
  5. Look at the 48h feed (/feed) for the specific error message returned by the platform API

Server not responding / website down

  1. SSH in and check: sudo systemctl status otb-pipeline
  2. If stopped: sudo systemctl start otb-pipeline
  3. If error on startup: journalctl -u otb-pipeline --since "5 min ago" to see the crash reason
  4. Common cause: a recent code push with a Python syntax error. Run python3 -m py_compile dashboard/main.py to check
  5. Check disk space: df -h. If full, clear old video files in the render output folder

Git pull blocked by DB file

git checkout dashboard/otb.db
git pull

The DB is excluded from git but sometimes shows as modified if the server created it with a different file mode. The checkout discards that and lets the pull proceed. The actual DB data is untouched.

Forgot email password reset emails are not arriving

  1. Check GMAIL_USER and GMAIL_APP_PASSWORD are set in keys.env
  2. Ensure the Gmail account has 2FA enabled (required for App Passwords)
  3. Try sending a test email from the server: python3 -c "import smtplib; s=smtplib.SMTP_SSL('smtp.gmail.com',465); s.login('YOU@gmail.com','APP_PW'); print('OK')"
  4. Check the client's spam/junk folder — Gmail automated emails sometimes land there on first send
  5. The Telegram reset link is always sent as well — use that as a fallback if email fails
